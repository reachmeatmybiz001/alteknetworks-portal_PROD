# Customer Details & Customer ID Final Fix

## Required customer ID
New customers are generated as:

`<initials>-<YYYY><4-digit sequence>`

Example:
- Motive Minds -> `MM-20260001`
- Next Motive Minds customer -> `MM-20260002`
- ABC Technologies -> `AT-20260001`

The backend uses an atomic DynamoDB counter in `ALTEKNET-Customers` keyed by year and customer code.

## Customer fields stored after creation
- Customer Name
- Address
- Contact Person
- Email ID
- Mobile Number
- Customer ID
- Created Date
- Status

The selected customer now also appears in a Customer Details card immediately below the customer selector, in addition to the customer table.

## Important deployment note
The screenshot showing `CUST-754787` proves the currently deployed Lambda is still using the previous customer-ID implementation. `CUST-*` IDs cannot be generated by this final backend code.

Deploy BOTH:
1. The Git repository ZIP through the existing Amplify/GitHub deployment process.
2. The Lambda ZIP to `ALTEKNET-UnifiedPortal-API`, or push `backend/**` to `main` so the GitHub Actions backend workflow deploys it.

Existing customers already stored with `CUST-*` IDs are not automatically renamed. Their missing details cannot be recovered unless those values exist elsewhere. New customers created after the backend deployment will use the new format and store all five requested customer fields.
